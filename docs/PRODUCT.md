# Product Definition

**상태:** Draft · MVP

**플랫폼:** Android first
**제품 영역:** Skincare purchase decision support

## 1. 한 문장 정의

SNS에서 발견한 스킨케어 제품을 공유하면 같은 제품의 콘텐츠를 묶고
근거를 비교해, 사용자가 구매 후보·보류·제외 결정을 내리도록 돕는다.

## 2. 비전

> 저장한 것을, 하게 만든다.

장기적으로는 SNS에서 발견한 상품·장소·행동을 실제 구매·방문·실행으로
전환합니다. 첫 시장에서는 스킨케어 구매 결정 하나에 집중합니다.

## 3. 해결할 문제

사용자는 여러 SNS에서 스킨케어 제품을 발견하지만 정보가 플랫폼별
저장함에 흩어집니다. 구매 시점에는 다음 작업을 반복합니다.

- 저장했던 콘텐츠를 다시 찾는다.
- 영상과 게시물에서 정확한 제품을 식별한다.
- 같은 제품에 관한 여러 주장을 다시 비교한다.
- 광고·협찬이 명시되었는지 확인한다.
- 유사한 제품 가운데 후보를 줄인다.
- 결국 살지 말지를 결정한다.

단순 북마크 통합만으로는 마지막 결정 단계가 해결되지 않습니다.

## 4. 첫 사용자

연령보다 행동으로 정의합니다.

- 인스타그램·유튜브·틱톡 등에서 뷰티 콘텐츠를 주 5개 이상 저장한다.
- 제품 구매 전 후기와 가격을 여러 번 다시 검색한다.
- 비슷한 목적의 제품을 중복 구매한 경험이 있다.
- 광고성 주장과 실제 사용 경험을 구분하기 어렵다고 느낀다.

## 5. 핵심 Job to be Done

> SNS에서 관심 있는 스킨케어 제품을 발견했을 때, 여러 출처를 다시
> 찾아다니지 않고 내가 살 후보인지 빠르게 판단하고 싶다.

## 6. 사용자 흐름

1. 사용자가 SNS 또는 브라우저에서 공유 버튼을 누른다.
2. 공유 대상에서 Ori Beauty를 선택한다.
3. 앱이 URL·텍스트를 우선 저장하고 즉시 완료 상태를 알린다.
4. 분석 결과로 제품 후보와 신뢰 수준을 제시한다.
5. 사용자가 후보를 확인하거나 직접 수정한다.
6. 동일 제품의 여러 출처를 하나의 제품 카드로 통합한다.
7. 사용자가 제품 상세 또는 비교 화면에서 근거를 확인한다.
8. 사용자가 `구매 후보`, `보류`, `제외` 중 하나를 선택한다.
9. 앱은 결정 시점과 선택적인 이유를 기록한다.

분석 실패가 저장 실패가 되어서는 안 됩니다. 원본은 수집함에 남고
사용자가 직접 제품을 지정할 수 있어야 합니다.

## 7. MVP 요구사항

| ID | 우선순위 | 요구사항 |
|---|---|---|
| P0-01 | Must | Android 공유 메뉴에서 URL·텍스트를 받을 수 있다. |
| P0-02 | Must | 분석과 무관하게 원본과 수집 시점을 먼저 보존한다. |
| P0-03 | Must | 분석 중·확인 필요·완료·실패 상태를 구분한다. |
| P0-04 | Must | 제품 후보를 제시하고 사용자가 확인·수정할 수 있다. |
| P0-05 | Must | 동일 제품으로 확인된 여러 출처를 하나로 묶는다. |
| P0-06 | Must | 요약된 주장마다 원본 출처를 확인할 수 있다. |
| P0-07 | Must | 구매 후보·보류·제외 상태를 설정하고 변경할 수 있다. |
| P0-08 | Must | 2~3개 제품을 한 화면에서 비교할 수 있다. |
| P0-09 | Must | 공유부터 결정까지 핵심 분석 이벤트를 기록한다. |
| P0-10 | Must | 사용자가 자신의 원본과 분석 결과를 삭제할 수 있다. |
| P1-01 | Should | 피부 고민과 현재 루틴을 선택적으로 등록할 수 있다. |
| P1-02 | Should | 현재 루틴과 목적이 겹치는 제품을 설명할 수 있다. |
| P1-03 | Should | 스크린샷 OCR로 제품 후보를 보완할 수 있다. |
| P1-04 | Should | 명시적인 광고·협찬 문구를 원문과 함께 표시한다. |

긴 온보딩은 첫 공유를 막지 않아야 합니다. 피부 고민과 현재 루틴은
비교에 필요할 때 점진적으로 요청합니다.

## 8. AI와 정보 표현 원칙

- 제품 매칭이 불확실하면 추측해 확정하지 않고 확인을 요청한다.
- 작성자의 주장은 `콘텐츠에서 언급됨`으로 표시한다.
- 광고 여부를 임의 추론하지 않고, 원문에서 확인되는 표시만 전달한다.
- 요약에서 원본보다 강한 효능 표현을 만들지 않는다.
- 현재 루틴과의 관계는 목적·역할의 중복으로 설명한다.
- 추천 또는 보류 이유에 사용된 입력을 사용자가 확인할 수 있어야 한다.
- 동의 없이 공유 원본을 별도의 모델 학습 데이터로 재사용하지 않는다.

## 9. 핵심 지표

### 북극성 지표: 7-day Saved-to-Decided Rate

제품 확인이 완료된 고유 제품 중 7일 안에 `구매 후보·보류·제외` 상태가
설정된 비율입니다.

```text
7일 내 결정된 고유 제품 수 ÷ 확인 완료된 고유 제품 수
```

동일 제품을 다룬 여러 콘텐츠는 분모를 늘리지 않습니다. 분석 실패와
미확인 후보도 분모에서 제외해 제품 인식 성능과 결정 성능을 구분합니다.

### 활성화

첫 실행 후 24시간 안에:

- 콘텐츠 3개 이상 공유
- 제품 1개 이상 확인
- 결정 1개 이상 완료

### 가드레일

- 잘못된 제품 매칭 신고율
- 근거 없는 주장 신고율
- 원본 유실 또는 중복 생성률
- 삭제 요청 처리 성공률
- 크래시 없는 세션 비율

첫 베타에서는 목표치를 임의로 고정하기보다 기준선을 수집한 뒤
목표를 설정합니다.

## 10. 수익화 원칙

초기 MVP의 목표는 결제보다 구매 의사결정 가치 검증입니다. 이후 제휴
링크·가격 비교·고급 루틴 기능을 검토할 수 있습니다.

- 제휴 수수료는 비교 결과나 표시 순위에 영향을 주지 않는다.
- 제휴되지 않은 제품도 동일한 기준으로 다룬다.
- 광고와 제휴 관계를 명확히 공개한다.
- `사지 않음` 또는 `보류`도 정상적인 성공 결과로 인정한다.
