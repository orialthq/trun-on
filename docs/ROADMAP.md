# Input-to-Organization Baseline Roadmap

목표 기간은 6주입니다. 일정 자체보다 매주 실제 Android 기기에서
검증할 수 있는 수직 흐름과 라벨링된 품질 데이터를 만드는 것을
우선합니다.

이번 로드맵의 범위는 다음과 같습니다.

```text
input → 원본 보존 → 분석 → 확인·수정 → 제품별 정리
```

제품 비교, 구매 후보·보류·제외, 개인 루틴 적합성, 가격·구매 연결은
이 베이스라인이 품질 기준을 통과한 뒤 별도 단계에서 다룹니다.

## 최종 완료 조건

실제 Android 기기에서 서로 다른 플랫폼의 스킨케어 콘텐츠 10개를
공유합니다. 입력 세트에는 다음 사례가 포함됩니다.

- URL과 공유 텍스트
- 스크린샷
- 하나의 콘텐츠에 여러 제품이 등장하는 사례
- 제품 라벨이 일부만 보여 식별이 애매한 사례
- 명시적 광고·협찬 표시가 있는 사례와 확인할 수 없는 사례
- 같은 제품을 다룬 여러 콘텐츠
- 이름이 비슷하지만 다른 제품

완료 시 다음이 모두 성립해야 합니다.

- 원본과 수집 시점이 하나도 유실되지 않는다.
- 중복 공유가 별도 콘텐츠로 무분별하게 생성되지 않는다.
- 자료 부족, 분석 중, 확인 필요, 정리 완료, 재시도 가능 상태를
  구분할 수 있다.
- 제품 언급과 콘텐츠의 진술이 원본 근거와 연결된다.
- 애매한 제품은 자동 확정되거나 기존 제품에 잘못 합쳐지지 않는다.
- 사용자가 제품 정보와 진술을 수정할 수 있다.
- 사용자가 제품 묶음을 합치고 분리할 수 있다.
- 콘텐츠 보관함과 제품 보관함에서 원본을 다시 확인할 수 있다.
- 원본과 파생 결과를 삭제할 수 있다.
- 앱 어디에도 구매 추천이나 개인 적합성 판단이 노출되지 않는다.

## 품질 게이트

베타 확대 전 100~200개의 실제 입력을 라벨링해 기준선을 만듭니다.
초기 가설 목표는 다음과 같습니다.

| 품질 기준 | 초기 목표 |
|---|---:|
| 입력 수신·원본 보존 성공률 | 99% 이상 |
| 지원 입력의 24시간 내 정리 완료율 | 80% 이상 |
| 사용자 1회 확인 후 정확한 제품 식별률 | 90% 이상 |
| 잘못된 자동 병합률 | 2% 이하 |
| 사용자에게 노출된 진술의 근거 연결률 | 100% |
| 표본 감사에서 원본에 없는 주장 | 0건 |
| 중복 Capture 생성률 | 1% 이하 |
| 확인 필요 항목 중앙 수정 시간 | 30초 이하 |
| 입력 10개의 공유부터 정리 완료까지 중앙 시간 | 5분 이하 |
| 삭제 성공률 | 100% |
| 원본 유실 | 0건 |

실제 기준선이 없는 숫자는 제품 약속이 아니라 검증할 가설입니다. 각
주차의 결과로 목표를 조정하되 잘못된 자동 병합, 근거 없는 진술,
원본 유실은 완화하지 않습니다.

## Week 1 — 범위 전환과 원본 계약

- [x] Flutter 앱과 Android/iOS 프로젝트 생성
- [x] Android `text/plain` 공유 수신
- [x] 앱 cold/warm start 전에 공유를 보존하는 native pending queue
- [x] `input → 분석 → 확인·수정 → 정리` 제품 범위 문서화
- [x] 기존 비교·결정·개인 기준 UI를 baseline 내비게이션에서 제거
- [x] `RawCapture`와 현재 처리 상태 데이터 계약 구현
- [x] 원본 URL과 정규화 URL 분리
- [x] transport event idempotency와 semantic fingerprint 기록
- [x] 콘텐츠/제품/확인 필요 화면과 빈 상태 골격

**완료 기준:** URL·텍스트 공유가 durable `RawCapture` 하나로 저장되고,
앱을 재시작해도 원본과 현재 상태를 확인할 수 있다.

## Week 2 — Durable capture와 콘텐츠 보관함

- [x] versioned 로컬 snapshot과 앱 재시작 후 영속화
- [ ] snapshot을 로컬 DB repository로 교체
- [x] durable snapshot 저장 뒤 native pending queue acknowledge
- [ ] 중복 공유 감지와 사용자 피드백
- [x] 콘텐츠 보관함 목록과 공유 원문 상세
- [ ] `received`, `source_limited`, `failed_retryable`, `unsupported`
  전체 상태 UI (`source_limited`와 실패 재시도 UI는 구현)
- [x] 분석 재시도
- [ ] 원본과 파생 결과 삭제
- [ ] Chrome, YouTube, Instagram, TikTok 공유 실기기 smoke test
- [ ] 민감한 원문·URL이 로그에 남지 않는지 검토

**완료 기준:** 분석 기능을 끈 상태에서도 입력 수신, 보존, 중복 감지,
재시도, 삭제가 안정적으로 동작한다.

## Week 3 — 분석 자료와 Golden Set

- [ ] 이미지 URI의 안전한 앱 전용 저장소 복사
- [ ] 이미지 MIME, 크기, 파일 수 제한
- [ ] 스크린샷 OCR과 OCR block 위치 보존
- [x] URL 정규화와 플랫폼 식별
- [ ] 접근 가능한 metadata와 사용자 입력 분리
- [ ] 사용자 메모와 콘텐츠 원문 분리
- [ ] 100~200개의 실제 입력 golden set 수집
- [ ] 제품 언급, 진술, 광고 표시, 제품 묶음 정답 라벨 작성
- [ ] 다제품·불명확·유사 이름·자료 부족 사례를 평가 세트에 포함

**완료 기준:** 각 분석 material이 어느 RawCapture의 어느 원문
범위 또는 이미지 영역에서 왔는지 추적할 수 있고, 반복 평가 가능한
라벨링 세트가 있다.

## Week 4 — 구조화 분석과 근거

- [x] `AnalysisRun`과 versioned output schema
- [ ] 분석 작업의 비동기 queue와 재개
- [x] `ProductMention`, `Statement`, `EvidenceRef` 구현
- [ ] 별도 `SourceDocument` material 계층
- [x] 브랜드·제품·카테고리·용량 단일 후보 추출
- [ ] 옵션·라인·리뉴얼 후보 추출
- [ ] 한 콘텐츠의 여러 제품 언급 추출
- [x] 일부 작성자 주장·사용 경험·사용법·단점 표현 분리
- [x] 명시적 광고·협찬 표시와 원문 추출
- [x] 필드별 confidence band와 unknown 지원
- [ ] 필드별 alternatives
- [x] 공유 텍스트 span `EvidenceRef`
- [ ] 이미지 영역 `EvidenceRef`
- [ ] evidence 없는 진술의 노출 차단
- [ ] schema 오류와 분석 재시도 처리

**완료 기준:** 평가 세트의 입력이 versioned schema로 분석되고, 사용자에게
보이는 모든 제품 필드와 진술에서 원본 근거를 열 수 있다.

## Week 5 — 확인·수정과 제품 정리

- [x] 제품 후보 확인과 핵심 필드 직접 수정
- [x] `제품을 특정할 수 없음` 흐름
- [ ] 콘텐츠 안의 제품 추가·삭제
- [ ] 잘못 추출된 진술 삭제와 유형·태그 수정
- [ ] append-only `Correction`과 되돌리기
- [x] 추출 `ProductMention`과 사용자 확인 제품 identity 분리
- [ ] 정밀도 우선 자동 병합 정책
- [x] 사용자 확인 후 완전 일치 identity만 병합
- [ ] 애매한 결과의 병합 제안
- [ ] 제품 묶음 합치기·분리하기
- [ ] 병합·분리 후 파생 보관함 재계산
- [x] 제품 보관함과 출처별 진술 상세

**완료 기준:** AI가 틀린 제품·진술·묶음을 사용자가 30초 안에 고칠 수
있고, 원본과 이전 분석 기록은 유지된다.

## Week 6 — 품질 측정과 소규모 베타

- [ ] `received → material_ready → analyzed → needs_review → organized`
  퍼널 계측
- [ ] 원본 보존, 분석 가능, 제품 식별, evidence coverage 측정
- [ ] 잘못된 자동 병합과 중복 생성 지표
- [ ] 수정률과 수정 시간 측정
- [ ] 24h Correctly Organized Rate 계산
- [ ] 삭제 성공과 잔존 데이터 검증
- [x] 도메인·분석·상태·위젯 테스트
- [ ] 오프라인·재시도·앱 종료·중복 공유 회귀 테스트
- [ ] 접근성, 로딩, 빈 상태, 오류 문구 검토
- [ ] 개인정보·보존 정책·의료 표현 가드레일 검토
- [ ] 5~15명 소규모 Android 베타
- [ ] 완료 조건의 10개 입력 end-to-end 시나리오 통과

**완료 기준:** 품질 게이트를 실제 데이터로 평가할 수 있고, 차단급
원본 유실·잘못된 자동 병합·근거 없는 진술·삭제 실패가 없다.

## 데이터와 실험 운영

모델 개선보다 먼저 평가 계약을 고정합니다.

1. 실제 사용자가 공유한 자료는 별도 동의 없이 학습 데이터로
   재사용하지 않습니다.
2. 평가용 입력은 명시적으로 동의를 받은 자료나 공개·가상 fixture로
   만듭니다.
3. 제품 식별, 진술 추출, evidence, 병합은 별도 점수로 평가합니다.
4. 전체 정확도 하나로 잘못된 자동 병합을 숨기지 않습니다.
5. 사용자 수정은 제품 실패 신호이면서 정답 라벨 후보로 저장하되,
   재사용 동의와 개인정보 정책을 따릅니다.

## 베이스라인 이후

다음 순서는 품질 지표와 사용자 행동을 보고 결정합니다.

1. 지원 플랫폼과 OCR 정확도 확대
2. 제품 식별과 중복 통합 정확도 개선
3. 대량 입력의 검색·필터·batch review
4. Android 베이스라인 계약을 이용한 iOS Share Extension
5. 별도 제품 실험으로 활용 단계 정의

활용 단계 후보에는 제품 비교, 개인 기준 연결, 구매 후보·보류·제외,
가격·구매 링크가 있을 수 있습니다. 그러나 현재 데이터의 제품 식별,
근거 연결, 병합 정확도가 품질 게이트를 통과하기 전에는 구현하지
않습니다.
