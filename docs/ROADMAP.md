# MVP Roadmap

목표 기간은 6주입니다. 일정 자체보다 매주 실제 Android 기기에서
검증 가능한 수직 흐름을 만드는 것을 우선합니다.

## 최종 완료 조건

- 실제 Android 기기에서 URL·텍스트·이미지를 공유할 수 있다.
- 공유 원본이 유실되지 않고 수집함에 표시된다.
- 제품 후보를 확인하거나 수정할 수 있다.
- 동일 제품을 다룬 출처가 하나로 묶인다.
- 2~3개 제품을 비교할 수 있다.
- 최소 1개 제품을 구매 후보·보류·제외로 결정할 수 있다.
- 핵심 제품 지표를 측정할 수 있다.
- 차단급 크래시·데이터 유실·개인정보 노출 문제가 없다.

## Week 1 — 기반과 제품 계약

- [x] Flutter 앱과 Android/iOS 프로젝트 생성
- [x] 기본 내비게이션과 디자인 토큰
- [x] `IncomingShare`, `Product`, `Decision` 데이터 계약
- [x] 수집·분석·확인·결정 상태 정의
- [x] 로컬 데모 데이터로 수집함·상세·비교·결정 흐름
- [x] Android `text/plain` 공유 수신과 durable pending queue
- [ ] 실제 Android 기기에서 공유 smoke test
- [ ] 개인정보와 의료 표현 가드레일 검토

**완료 기준:** 새 환경에서 앱을 빌드하고, 샘플 데이터로 수집함부터
결정까지 이동할 수 있다.

## Week 2 — Android 공유와 수집함

- [ ] 이미지 URI의 안전한 앱 전용 저장소 복사
- [ ] 원본 로컬 저장과 중복 요청 방지
- [ ] 공유 성공·실패 피드백
- [ ] 앱 재시작 후 수집함 유지
- [ ] Chrome, YouTube, Instagram, TikTok 실기기 테스트

## Week 3 — 제품 추출과 사용자 확인

- [ ] 비동기 분석 인터페이스와 오류·재시도 처리
- [ ] 브랜드·제품명·용량 후보 추출
- [ ] 후보 확인과 수동 수정
- [ ] 원본 링크·이미지와 결과 연결
- [ ] 낮은 신뢰도의 자동 확정 금지

## Week 4 — 통합 제품 카드와 결정

- [ ] 동일 제품의 여러 출처 통합
- [ ] 출처별 주장과 명시적 광고·협찬 표시
- [ ] 결정 이유와 변경 이력
- [ ] 원본·제품·결정 삭제

## Week 5 — 비교와 측정

- [ ] 선택적인 피부 고민·현재 루틴 영속화
- [ ] 목적·역할 중복 설명 개선
- [ ] 핵심 이벤트와 Saved-to-Decided 퍼널
- [ ] 접근성 및 빈 상태 검증

## Week 6 — 안정화와 소규모 베타

- [ ] 핵심 흐름 단위·위젯·통합 테스트
- [ ] 실제 기기 및 공유 출처 회귀 테스트
- [ ] 로딩·오프라인·재시도 정리
- [ ] 개인정보·삭제·의료 고지 검토
- [ ] 5~15명 소규모 베타

## MVP 이후

1. 제품 인식과 중복 통합 정확도 개선
2. 루틴 중복 설명과 비교 품질 개선
3. 가격·구매 링크 실험
4. 알림과 재구매 시점
5. iOS Share Extension
6. 스킨케어 외 카테고리 확장
